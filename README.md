# Manga.

A tiny, static, mobile-first manga reader. No build step, no backend — just
HTML/CSS/JS files plus a folder of images. Host it anywhere that serves
static files (GitHub Pages, Netlify, a spare corner of any web server) or
run it locally.

## Try it now

The site ships with two short demo chapters (original placeholder art, not
real manga) so you can see it working immediately:

```bash
cd manga-reader        # this folder
python3 -m http.server 8000
```

Then open **http://localhost:8000**.

> **Important:** open it via `http://localhost:...`, not by double-clicking
> `index.html`. Browsers block a page's `fetch()` of local files over the
> `file://` protocol, which is how this site loads `chapters.json` — so it
> needs a (very lightweight) local server. Any static server works, e.g.
> `npx serve`.

## Adding your own chapters

1. Delete (or keep, your call) the two demo folders in `chapters/`.
2. Make a new folder per chapter under `chapters/`, e.g. `chapters/chapter-3/`.
3. Drop the page images in, named so they sort in reading order:
   `001.jpg`, `002.jpg`, … `010.jpg` (zero-padded so `010` doesn't sort
   before `002`). Supported formats: jpg, jpeg, png, webp, gif, svg, avif.
4. Regenerate the manifest:

   ```bash
   python3 generate_manifest.py
   # or: node generate_manifest.js
   ```

   This rewrites `chapters.json` by scanning `chapters/`. It auto-titles new
   chapters from the folder name (e.g. `chapter-3` → "Chapter 3") and
   **preserves any title you've hand-edited** for chapters it already knew
   about. Run it again any time you add or rename a chapter folder.
5. Refresh the library page.

To rename a chapter, just edit its `"title"` in `chapters.json` directly —
the generator won't overwrite a title that's already set.

To rename the library itself, edit the top-level `"title"` in
`chapters.json` (shows as the browser tab title).

## What's in here

```
index.html            the library / home page
reader.html            the reader
css/style.css          all styles (light + dark theme)
js/common.js            shared helpers: theme, settings, progress, manifest loading
js/home.js              renders the library grid + "continue reading" card
js/reader.js            the reader itself: scroll & page modes, swipe, progress
chapters.json           the manifest (regenerated by the scripts below)
chapters/…              your page images, one subfolder per chapter
generate_manifest.py    rebuilds chapters.json (Python, no dependencies)
generate_manifest.js    same thing, if you'd rather use Node
```

## Reading features

- **Scroll or page mode** — continuous vertical scroll, or one page at a
  time with tap zones / swipe / arrow keys.
- **Direction** — left-to-right or right-to-left, for reading order on
  chapter navigation and page-mode taps.
- **Light / dark theme** for the library and settings; the reading canvas
  itself always stays dark for comfortable reading.
- **Progress is remembered per chapter** (in the browser's local storage,
  nothing sent anywhere) and surfaces as a "Continue reading" card on the
  library page.
- **Next chapter** button at the end of each chapter, using the order
  chapters appear in `chapters.json`.

All settings and progress live in `localStorage` on the reader's own
device/browser — there's no account system and no server-side storage.

## Deploying

Any static host works. For GitHub Pages: push this folder to a repo, enable
Pages for that repo (or the `docs/` folder), done. For image-heavy chapters,
keep an eye on repo size — consider `.webp` for smaller files at similar
quality, or hosting images in a CDN/bucket and pointing `chapters.json`'s
`folder` values at that instead of `chapters/...`.
